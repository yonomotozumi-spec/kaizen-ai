# AIツール — Kaizen AI

コンサル業務で使う自社製AIツール。**「自らAI経営を実践」の実証**であり、商談デモにもそのまま使えます。

| ツール | 何をするか | 実行環境 | 生成AI利用 |
|---|---|---|---|
| `gyomu-shindan.html` | **業務改善診断ツール**。業務を棚卸しして入力すると、年間工数・人件費・AI削減見込み・着手優先順位・投資回収期間をその場で算出 | ブラウザのみ | なし |
| [`ocr/`](ocr/) | **紙の書類 → データ化**。請求書・領収書・納品書をスキャン画像/PDFから読み取り、項目をCSVに落とす | Python + Tesseract | **なし（トークン消費ゼロ）** |
| `gijiroku.py` | 会議の文字起こし → 構造化議事録（決定事項・TODO表・論点・保留事項） | Python + APIキー | あり |
| `teiansho.py` | 顧客ヒアリングメモ → 社内テンプレート準拠の提案書ドラフト（料金はサービスカタログ参照） | Python + APIキー | あり |

> **トークン課金が発生するのは `gijiroku.py` と `teiansho.py` だけです。**
> 診断ツールとOCRツールは生成AIを使わないため、何回動かしても費用はかかりません。

## 業務改善診断ツール（`gyomu-shindan.html`）— 商談デモ用

**ファイルをダブルクリックしてブラウザで開くだけ。** インストール・APIキー・ネット接続すべて不要。
商談の場でノートPC・タブレットを相手に向けて、その場で数字を入れながら使うことを想定しています。

### 商談での使い方（想定5〜10分）

1. **「サンプルを入れる」** を押す → 中堅企業の想定データで診断結果が即表示される（つかみ）
2. 「御社だとどうですか？」と聞きながら、**その場で業務名・時間・人数を書き換える**
3. 数字が動く → **削減見込み額・優先順位・投資回収期間**が即座に再計算される
4. **「印刷 / PDF」** でその場でPDF化して置いてくる／**「CSV出力」** でExcelに渡す
5. → 「この概算を実測ベースで確定させるのが**業務診断（アセスメント）**です」と[サービスカタログ](../docs/services/service-catalog.md)へつなぐ

### 算出ロジック

| 項目 | 算出方法 |
|---|---|
| 年間工数 | 年間実施回数 × 1回の所要時間 × 関与人数（毎日＝年間営業日数を参照） |
| 年間人件費 | 年間工数 × 平均時間単価（法定福利費・間接費込みを推奨。初期値3,000円） |
| 削減見込み | 年間工数 × 削減率（業務の種類ごとの目安を自動入力／個別に上書き可） |
| 優先度スコア | 効果（最大値=100の相対値・平方根スケール） × 実現しやすさ係数（難易度 低1.0／中0.7／高0.35） |
| 優先度 | スコア 55以上=A（即着手）／22以上=B（次に着手）／22未満=C（当面見送り） |
| 想定投資額 | 難易度別の目安（低30万／中80万／高200万）× 優先度Aの件数。直接入力で上書き可 |
| 投資回収期間 | 想定投資額 ÷（Phase1の年間削減額 ÷ 12） |

削減率・難易度の前提はツール内の「削減率・難易度の前提」を開くとその場で提示できます。
**承認・調整・折衝（20%）や対面・現場作業（10%）は意図的に低く設定**しており、
「AIでやるべきでない業務は見送りと明示する」ことが誠実さの訴求ポイントになります。

### 運用ルール

- 出力は**概算シミュレーション**です。確定値として提示しないこと（ツール内にも免責を明記済み）
- 入力データは**ブラウザのlocalStorageにのみ保存**され、外部送信は一切ありません（顧客先で使っても情報は残らない＝そのまま説明可）
- 顧客ごとに使い回す場合は、商談後に「クリア」を押すこと
- 時間単価・削減率を顧客有利に盛らない。**盛った瞬間に診断の信頼が消える**

## 紙の書類 → データ化（[`ocr/`](ocr/)）— トークン消費ゼロ

請求書・領収書・納品書のスキャン画像やPDFを読み取り、項目をCSVに落とします。
**生成AIを使わないため、何枚処理してもAPI課金は発生しません。** すべてローカル処理で、
書類が外部に送信されることもありません（顧客の機密書類を扱う前提）。

```bash
sudo apt install tesseract-ocr tesseract-ocr-jpn tesseract-ocr-jpn-vert poppler-utils
pip install -r ocr/requirements.txt

python3 ocr/ocr.py ocr/samples/            # 同梱サンプルで動作確認
python3 ocr/ocr.py scans/ -o 結果.csv       # フォルダ一括処理
```

- 電子請求書のPDFは**テキスト層から直接抽出**するのでOCRを通らず、誤認識ゼロ
- スキャン画像は 拡大 → 傾き補正 → **罫線除去** → OCR → 誤認識の規則補正 → 項目抽出
- **検算**（小計＋税＝合計、明細合計＝小計、税率、日付の前後、登録番号の形式）で誤読を自動検出
- 読めなかった項目は `（要確認）` と明示。推測で埋めない

### 実測した精度（書式6種 × 画質5段階 = 30通り / 190項目）

| 条件 | 項目正解率 | 誤り率 |
|---|---|---|
| PDFにテキスト層あり（電子請求書） | 100% | 0% |
| 200〜300dpiのスキャン | 92〜95% | 0〜2.6% |
| 150dpiのスキャン | 84% | 0% |
| **100dpi以下** | **5%以下** | — |

**150dpiと100dpiの間に断崖があります。** また **OCR信頼度85以上に限れば誤り率は0%** でした。
自動処理に回すしきい値として使えます。

**危険なのは未検出ではなく誤読です。** 未検出は `（要確認）` と出るので気づけますが、
誤読は気づけません。請求書は検算（小計＋税＝合計）で守れますが、
**領収書・レシートの金額と、全帳票の日付・番号は検算では守れない**ため目視確認の対象にしてください。

`bench.py` で顧客の実物を使って同じ計測ができます。
**商談ではサンプルの数字ではなく、顧客の実物を10〜20枚読ませた結果を提示すること。**

詳細は [`ocr/README.md`](ocr/README.md) を参照。

## Pythonツールのセットアップ（初回のみ）

```bash
cd tools
pip install -r requirements.txt

# APIキーを環境変数に設定（https://platform.claude.com で取得）
export ANTHROPIC_API_KEY=sk-ant-...
```

> ⚠️ **APIキーは絶対にコミットしない。** `.gitignore` で `.env` 等は除外済みですが、
> コードやメモへの直書きも禁止。環境変数または `.env`（ローカルのみ）で管理すること。

## 使い方

### 議事録要約

```bash
python gijiroku.py 文字起こし.txt
python gijiroku.py 文字起こし.txt -o 議事録.md --title "◯◯社 定例会議" --attendees "田中, 佐藤"
```

- 出力: `<入力名>_議事録.md`（`-o` で変更可）
- 文字起こしにない情報は推測せず「（要確認）」と明記する設計

### 提案書ドラフト生成

```bash
python teiansho.py ヒアリングメモ.txt --client "サンプル商事"
```

- テンプレート: [`../templates/proposal-template.md`](../templates/proposal-template.md) に自動準拠
- 料金: [`../docs/services/service-catalog.md`](../docs/services/service-catalog.md) のレンジ内で提案
- 不明点は「（要確認: 〜）」として残す設計 — **推測で埋めない**

## 運用ルール

1. **生成物は必ず人が確認してから使う** — 特に提案書の金額・スコープはオーナー承認必須（ガバナンスのレッドライン）
2. **顧客の機密情報を入力する場合** — 顧客との合意（生成AI利用可否・学習利用オフ）を事前に確認（`templates/engagement-checklist.md` 参照）
3. 生成コスト目安: 1回あたり数十円〜数百円（入力量に依存。実行後にトークン数が表示される）

## 技術メモ

- モデル: `claude-opus-5`（Anthropic）、ストリーミング出力
- 実行には Python 3.10+ が必要
