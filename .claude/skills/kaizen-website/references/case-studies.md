# 事例の書き方

Kaizen AI は2026年設立で、公開できる実績がまだ少ない。この状況で事例ページを持つこと自体は正当だが、**実例と想定モデルケースの線引きが崩れた瞬間に経歴の詐称になる。** ここは飾りではなく、会社が掲げている「誠実なAI活用」が実際に守られているかが最初に現れる場所でもある。

## 2種類を必ず分ける

| | 実例 | 想定モデルケース |
|---|---|---|
| バッジ | 「実例」（朱の塗り） | 「想定ケース」（真鍮の枠） |
| アンカー | `#case-<内容>` | `#case-01`〜 |
| 数値 | **実測値のみ** | 試算。前提と測り方を必ず併記 |
| 顧客名 | 掲載許可があれば実名、無ければ業種のみ | 架空 |

`cases.html` は実例を先に置き、想定ケース群の前に「ここから先は、想定モデルケースです。」という区切りの見出しを入れる。トップページでは「実例」「想定モデルケース」の2グループに分けて並べる。

注意書きは**両方のページに常時表示**する。トップから事例ページに飛ばずに離脱する読者にも届く必要があるため。

## 無い数字は書かない

実例に時間削減の数字が無いなら、**無いまま出す**。想定ケースと形を揃えたくなるが、そこで推測を入れると全体の信用が飛ぶ。

代わりに書けるものがある:

- **数えられる事実** — 「DD項目18項目のうち9項目が自動」「39法令のうち5法令に自動反映」
- **工程の変化** — 「議事録作成後の手作業 2ステップ → 0」
- **精度の変化** — 「住所の代表点（最大716mのズレ）→ 案件の緯度経度」

いずれも実装から確認できる。数値の根拠は `website/README.md` に対応表として残し、後から誰でも検証できるようにする。

## 効果の表には「測り方」の列を置く

```
| 指標 | Before | After | 測り方 |
```

「数字で語る」を掲げている会社が、その数字の出どころを書かないと成立しない。「作成開始〜共有までの実測（前後10回の平均）」「週3回×4週で換算」のように、実測なのか換算なのかまで書く。これは想定ケースでも同じ（試算の根拠として機能する）。

## 「この案件で大事にしたこと」を必ず書く

効果の表の下に、**自動化しなかったこと**とその理由を書く。

- 「農地・森林・埋蔵文化財は、機械的に判定すると誤りが混ざるためあえて人に残した」
- 「浮いた50時間がそのまま売上になるとは書きません。商談に振り向けられる時間が生まれる、というところまでが確かなこと」
- 「人員を減らす前提の試算ではありません」

実務を分かっている読者ほど、全自動を謳う会社より**線を引ける会社**を信用する。これは謙遜ではなく、判断力の提示として機能している。

## 実装の流れを図にする

各実例に、何が何に繋がっているかを示すSVG図を1枚。装飾ではなく、**議論が乗っている部分だけを描く**。

- 前後を比較するなら、その差分を描く（分断された手作業 → 一本に繋がった経路）
- 矢印には必ずラベルを（`自動投入` `該当判定` `手作業`）
- 強調色は意味を持つ要素にだけ（人の判断が残る箇所、精度の問題が起きていた箇所）

書き方は `artifact-diagramming` スキルに従う。

## グラフを入れるとき

**グラフは数字を実際以上に権威づける。** だから:

- 想定ケースのグラフは、「想定モデルケース」の見出しと注意書きが**同時に視界に入る位置**に置く
- 実例に実測値が無いなら、実例のグラフは作らない。実数（項目数・法令数）だけを扱う
- 単位の違う複数ケースを並べるなら、「人がやる量の削減率」のように**一つの軸に揃えてから**。二軸グラフは作らない

配色と検証手順は `references/design-system.md` と `dataviz` スキル。

## 顧客名を出す前に

**先方の掲載許可を必ず取る。** 業種と規模だけでも特定されうるので、匿名化したつもりでも安全とは限らない。許可の有無が不明なうちは業種のみの表記にし、`website/README.md` の「未確認・要対応」に書き残してユーザーに伝える。

## 情報が足りないとき

事例の一部を推測で補ったなら、**どこを補ったかを明示する**。`website/README.md` に「この手順は他の案件の設計方針から補って書いた記述。実際の運用と違えば修正すること」と残し、報告でも触れる。黙って埋めると、後から誰も見分けられなくなる。

## 実績が出たら

想定モデルケースを実例に差し替える。そのとき注意書きも一緒に外す。**注意書きだけ外して数値を残すのが最悪の状態**なので、必ずセットで扱う。
